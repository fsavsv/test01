                            充电器通用升级协议

5 物理接口 
本标准物理层采用 CAN2.0B 协议标准，通信速率为 250Kbps。 本标准的物理层数据帧格式遵循 CAN2.0B 标准，使用 29 位的扩展仲裁域格式（标识符）。 按标准先发送高位，再发送低位。

5.1 标识符
 
[TABLE]
ID28~ID26 | ID25 | ID24 | ID23~ID16 | ID15~ID8 | ID7~ID0
保留 RES | 保留 RES | 分包标识符CNT | 功能码Function Code | 源地址Source Addr | 目的地址Dest Addr
[/TABLE]
分包标识符 CNT 
用于大数据包的分包发送/接收标识。如果 CNT=1，表示数据包含下一帧，而且它有相 同的功能码、源地址和目的地址。如果 CNT=0，表示是数据包的最后一帧数据。如果数据包 只需要一帧传递，则 CNT=0。

功能码（Function Code）
 命令的功能类型，表示数据信息对应的功能类型。
 源地址（Source Addr）
 源地址表示该帧是由哪个设备发出。
 目的地址（Destination Addr）
 目的地址表示该帧的接收设备。
5.2 地址编码
在本标准中地址编码规格如下： 1. 充电器模块物理范围从 1~N表示，地址由充电器上拨码开关设定，五路充电器N最大为3，四路充电器N最大为15；

6.2 Boot/APP 跳转指令
用于从节点执行指定类型的固件程序，该指令带有固件类型参数。若该指令的固件类型 参数为 BOOT，而当前节点运行在 APP，那么该节点收到此指令后应立即跳转到 BOOT 代码。 反之亦然。 
该指令不需要从节点应答，从节点运行的固件代码类型通过信息获取指令来得到，以此 来判断固件代码是否成功跳转。 
节点地址：充电器模块实际地址 1~N，N为拨码最大值 
⚫ BOOT 和 APP 下都需要对应该功能码

6.3 擦除扇区（Erase）
用于 APP 程序存储区域的 Flash 扇区擦除，该命令无参数。主机发送该命令后，从节点 先擦除 Flash 扇区，再通过应答帧返回是否擦除成功的结果。 
节点地址：充电器模块实际地址 1~N，N为拨码最大值  
⚫ 仅 BOOT 下需要对应该功能码，非 Boot 下不做应答； 
⚫ 由于 Flash 擦除时间比较长，允许最长应答时间为 10s

6.4 Write Info
为了提高固件升级速度，采取发送一定量的固件数据之后才进行烧写，比如从节点接收 到 1024 字节之后才将固件数据写入芯片内部的 Flash 中，所以在传输数据之前，应该先发送 该命令，告诉从节点即将缓存的固件数据字节数以及固件烧写的偏移地址，所以该命令带有 两个参数：固件数据偏移地址和缓存的固件数据字节数。主机发送该命令后，可以通过从节 点返回的结果判断操作是否成功。 
节点地址：充电器模块实际地址 1~N，N为拨码最大值
 ⚫ 仅 BOOT 下需要对应该功能码，非 Boot 下不做应答。

6.5 Write
主机向从节点发送固件数据，发送的总数据字节数为 Write Info 命令的“缓存固件数据 字节数”指定的字节大小。 
由于 CAN 每帧数据最多只能带 8 字节数据，所以采用分包循环发送方式连续发送大于 8 字节数据。当发送数据时，ID 域的分包标识符用于当前包标识，1—表示后续还有数据，0— 表示没有后续帧。
 数据域的 Byte1 为包序列号，从 0 开始直到 145（限制每包最大传输升级数据1022字节），再从 0 开始滚动。数据域的 Byte2 为 低地址数据，依次放入，Byte8 为高地址数据，当数据不满 8 字节时，不需要填充，按实际 字节数发送即可。当“缓存固件数据字节数”的字节数据全部发送完毕之后，从节点应该验 证数据的正确性，若数据正确则将数据写入 APP 存储区，然后向主机返回本次烧写是否成功 的应答帧。 
节点地址：充电器模块实际地址 1~N，N为拨码最大值 
⚫ 仅 BOOT 下需要对应该功能码，非 Boot 下不做应答；
 ⚫ 连续发送的数据帧 ID 的 CNT 值为 1，最后一帧数据的 CNT 值为 0；
 ⚫ 写 Flash 时间可能比较长，允许的最长应答时间为 1s；
 ⚫ 当收到数据包的最后一帧数据后（即 CNT 值变为 0 的数据包），如果数据包的总字 节数不等于指定的数据包字节数时，应该应答失败。
